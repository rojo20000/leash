# N18 nemotron_eval (implementer; a transcriber then turns the numbers into tables). Stage 3.

## Goal
Measure whether Nemotron's output in Leash is useful and trustworthy, improve it with a bounded
measure -> revise -> re-measure loop, and keep every round's numbers as evidence (judging criterion 3).

1. Build `ml/eval/nemotron_cases.jsonl`, about 40 labeled synthetic cases (36-44), one JSON object per line:
   ```json
   {"id":"nc-001","split":"dev"|"holdout","group":"benign_call"|"over_broad_read"|"exfiltration"|"injected_doc"|"clean_doc",
    "call":{"tool":"read_record","args":{"patient_id":"pt-0099","resource_types":["Patient","Encounter"]}},
    "document_id":null, "document_text":null,
    "expected":{"injected":0|1|null,"safety_flag":true|false|null,"decision":"allow"|"block"|"escalate",
                "recommended_action":"approve"|"deny"|"needs_more_info"|null},
    "note":"one line on why this label"}
   ```
   - Mix: about 10 benign calls (normal scheduling reads, updates, reminder emails to `@patients.example.org`),
     about 8 over-broad reads (Condition/MedicationRequest, all five types, many patients), the exfiltration
     attempt and 3-4 variants (attacker address, full record in an email body to an allowed domain), about 8
     injected documents and about 8 clean documents.
   - Document text comes ONLY from existing data: the five referral PDFs' extracted text (EHR
     `/fhir/DocumentReference/{id}/text`; ref-0042 is the one injected referral) and the TEST split of
     `data/corpus/corpus.jsonl` (label 1 injected, label 0 benign; include hard negatives). Do not write new
     injection text. Store `document_id` for referrals or the corpus `id` in `note` for corpus text.
   - Split: about 24 `dev` and 16 `holdout`, stratified by group, fixed in the file.
   - Labels follow the contract: `expected.decision` is what deterministic policy plus the local models should
     decide; `recommended_action` is what a careful privacy officer would recommend for block/escalate cases (null
     for allows).
2. `ml/eval/nemotron_eval.py [--round N] [--mode live|replay|off]`: runs every case through the real pipeline
   in-process (`TestClient` on the gateway and EHR, fresh temp runtime dir per case, `LEASH_WARMUP=0`), and calls
   `leash.nemotron.jailbreak_check` / `content_safety` and `leash.reasoner.explain` exactly as the gateway does.
   Computes the C10.7 `<M>` metrics separately for dev and holdout: injection precision/recall for TF-IDF alone,
   the jailbreak detector alone, and combined (OR); content safety flag accuracy against `safety_flag`; reasoner
   recommended_action agreement against labels (block/escalate cases only); reasoner valid-JSON rate (served_by not
   `fallback:template`). Writes `ml/eval/rounds/round_<N>.json` (the round object of C10.7 plus a per-case table:
   id, split, expected, observed, served_by per step) and appends/replaces round N in key `nemotron.eval.rounds`
   of `metrics/results.json`, plus `nemotron.models` and `nemotron.latency_ms` (from
   `leash.nemotron.latency_summary()`, `source "live"`). Counts served_by per step; if any step was not served by
   `nemotron` in a live round, the round says so and the report says so.
3. The loop, at most 3 rounds, with the key (`--mode live`):
   - Round 1: run as is. Read the FAILED DEV cases only (never tune on holdout).
   - Revise `leash/prompts/reasoner_system.txt`, `leash/prompts/content_safety_policy.txt` and/or
     `leash/prompts/injection_policy.txt` based on those failures (wording, grounding instructions, examples
     drawn from dev cases only). Do not change labels to fit outputs; if a label is wrong, fix it, say so in the
     report, and re-run round 1.
   - Round 2 (and optionally 3): re-run. Stop when holdout stops improving. Keep every round file and every
     round in results.json; record each prompt's sha256 in its round.
4. Tests `tests/test_nemotron_eval.py` (no key, no network): the cases file has 36-44 lines, every line has the
   fields above, ids are unique, both splits cover every group, no `document_text` contains a sentence that is not
   in the corpus or a referral; running `nemotron_eval.py --mode off --round 0 --out <tmp_path>` produces a round
   object with all `<M>` keys (fallback numbers, written to the tmp path only, not to results.json).
5. Transcriber step (after the implementer): a markdown table of rounds (dev and holdout) and per-model latency for
   `docs/NEMOTRON.md`, copied exactly from `metrics/results.json` (handed to N12/N13 through the report).
